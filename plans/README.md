## Findings considered and rejected (round 2)

(So nobody re-audits these.)

- **"`addSystemLog` in OutputFrame's `sandboxHtml` useMemo deps forces
  recomputation"** — wrong: `addSystemLog` is a stable `useCallback([])`;
  an unchanged dep never triggers recomputation. The real (small) issue at
  that site is the `setLogs` call *inside* the memo (a render-phase side
  effect), which plan 008 removes in passing.
- **"dompurify is bundled into the published library"** (as stated by the
  audit) — overstated: `CodeEditor.tsx` imports only `@monaco-editor/react`,
  which loads Monaco from a CDN at runtime; the installed `monaco-editor` /
  `dompurify` packages are an audit-tree issue for consumers, not shipped
  code. The advisories are still worth clearing cheaply — plan 010.

## Findings considered and rejected (round 1 — kept for the record)

- **"localStorage key collision when `persistenceKey` is omitted"** — wrong:
  every read/write path in `useSandboxState.ts` guards on `persistenceKey`;
  omitting the key is the documented ephemeral mode.
- **"Replace `postMessage(..., '*')` targetOrigin with a real origin"** —
  would break the component: the sandbox iframes are `srcDoc` without
  `allow-same-origin`, so their origin is opaque and `'*'` is the only valid
  targetOrigin. The correct hardening (event.source checks) was plan 002.
- **"Vitest 4 / Vite 5 incompatibility"** — misdiagnosis; the real issue
  (`defineConfig` import source) was fixed in plan 001.
- **"Deduplicate react.ts/react-ts.ts and express runner templates via factory
  functions"** — superseded: plan 003 deleted that legacy layer.
- **Express route-param regex robustness** (`express.ts`) — real but
  marginal; same edge behavior as several real-Express cases.
- **Prettier / husky / pre-commit hooks** — low leverage for a solo repo with CI.

(non-interactive run; features are the maintainer's choice). Top candidates:

   `ServerOutput.tsx:48` hardcodes `const [method] = useState('GET')` with no
   setter; `template_descriptions/express.md` says "GET only"; the transport
   (`sendSimulatedRequest`) already accepts arbitrary methods. Clearly stopped
   mid-implementation. Note: the Express mock only implements `app.get` and
   resets routes to `{ GET: {} }` (`runner.ts` express recipe), so this also
   needs mock-side `post/put/delete` support. Coarse effort: M. (Also

   fully built and referenced nowhere; `docs.ts:getDocsForMode` returns docs

   toolbar toggle and grow `docs.ts` per mode (M, extends the learner-facing
   theme of plans 006/007), or delete both files as dead code (S). Keeping
   unwired ships dead weight and confuses contributors — pick one.

   just shipped a fixed two-file `WebFileBundle` (`index.html` + `style.css`)
